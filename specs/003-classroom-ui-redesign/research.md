# Research: Classroom UI Redesign

**Feature**: `003-classroom-ui-redesign` | **Date**: 2026-10-03
**Input**: spec + user technical brief (single theme module, QSS generation,
QPainter board surface, stateful mic button, SVG icons, status pill,
offscreen regression at two sizes, contrast tests)

No NEEDS CLARIFICATION: the brief prescribes each mechanism; the spec
locks every visual target.

## Decisions

### R-01: Single theme module generating QSS

- **Decision**: Extend `ui/theme.py` into the sole visual authority:
  color tokens, font sizes, spacing, radii, state palettes; a
  `build_stylesheet()` function renders the whole application QSS from
  tokens (no hand-written QSS fragments in widgets). Widgets reference
  tokens for paint code; QSS covers buttons, labels, dialogs, focus.
- **Rationale**: FR-011 by construction — a token rename breaks visibly
  in one place instead of drifting across files.
- **Alternatives rejected**: Per-widget stylesheets (the drift that
  caused the current contrast bug); Qt Designer `.ui` files (opaque,
  untestable values).

### R-02: Board surface in paintEvent

- **Decision**: `BoardView.paintEvent` draws, in canvas space: soft shadow
  (layered translucent rounded rects), lighter slate fill
  (`board_surface`), 2px border, 24px corner radius — then elements, then
  selection outline + square corner handles, then highlight ring.
  Letterbox margins keep the darker window background so the surface is
  unmistakable.
- **Rationale**: FR-001/FR-007 with zero layout cost; handles are painted
  adornments (non-interactive in V1 — selection itself is unchanged).
- **Alternatives rejected**: Stylesheet-rounded widget (can't ring only
  the canvas rect inside letterbox space); separate frame widget (extra
  layout, resize lag).

### R-03: Stateful circular mic button

- **Decision**: `MicButton(QPushButton)` subclass with a `voiceState`
  property (`idle|listening|processing|validating|executing`); per-state
  ring/background repainted in `paintEvent`; listening pulse via
  `QPropertyAnimation` on a `pulse` property (~1 Hz, static ring when
  reduced-motion is requested); fixed 112px circle; icon drawn from the
  bundled mic SVG, tinted per state.
- **Rationale**: FR-003 + FR-008 (hover/pressed/disabled/focus come from
  the generated QSS; the state ring is paint, always in sync with the
  property tests read).
- **Alternatives rejected**: Five swapped stylesheets (pulse needs
  animation, not snapshots); emoji text button (current bug, FR-004 bans
  it).

### R-04: Bundled SVG icons via QIcon

- **Decision**: Vendor a minimal SVG set (mic, undo, redo, window,
  check, alert, question, error-dot, state dots) under
  `src/smartboard/ui/icons/` (Lucide-style stroke icons, currentColor
  strokes recolored at load to the theme text color); loaded once in an
  `icons.py` cache returning `QIcon`s. No emoji anywhere in chrome.
- **Rationale**: FR-004 + sharp at every scale/DPI, unlike emoji or PNGs.
- **Alternatives rejected**: System theme icons (absent/unpredictable on
  classroom Windows); emoji (rendering varies, unprofessional).

### R-05: Status pill + result chip driven by pipeline state

- **Decision**: `StatusPill` (small `QWidget`) and `ResultChip`
  (`QLabel`-based) render `(text, color, icon)` triples from theme maps
  keyed by the existing state strings (`Idle…Executing`) and outcome
  strings (`Done…Error`). Main window updates them from the same
  `orchestrator.status` / result dict the logic already produces — the
  pill/chip own no state machine.
- **Rationale**: FR-002/FR-004 without duplicating state logic; "never
  color alone" enforced because the triple always includes icon + text.
- **Alternatives rejected**: New status enum (would fork the pipeline
  vocabulary and risk drift).

### R-06: Offscreen visual regression at two sizes

- **Decision**: pytest-qt + `QWidget.grab()` at 1366×768 and 1920×1080:
  hash-anchored II structural assertions (surface rect centered, border
  present via pixel sampling, chip/pill text present, button geometries)
  rather than brittle full-image hashes, PLUS one stored reference PNG
  per size with a tolerant pixel-diff gate (≤0.5% differing pixels)
  regenerated by an explicit `--regen-refs` run, never silently.
- **Rationale**: User-brief directive made robust — catches layout drift
  without failing on font-rendering noise between machines.
- **Alternatives rejected**: Pixel-perfect hashing (fails across GPUs/
  font versions); no regression shots (the 002 tofu episode proved their
  worth).

### R-07: Contrast tests on token pairs

- **Decision**: Pure luminance tests over every `(text, background)` token
  pair the theme declares (normal text ≥4.5:1, large text/controls ≥3:1),
  computed with the WCAG relative-luminance formula. Any new token pair
  fails closed until measured.
- **Rationale**: FR-006/SC-002 as a unit test instead of a human judgment.
- **Alternatives rejected**: Manual checklist only (regresses silently).

### R-08: Title and Esc

- **Decision**: Title exactly `"Smart Chalkboard"`; Esc keeps closing
  dialogs first, window second (existing behavior retained, suffix text
  removed).
- **Rationale**: FR-010 with no behavior change (spec assumption).
